# 医保报销计算器 MVP 设计

## 目标与交付边界

本项目是企业 AI 实践测试的可评估 MVP，而不是实时接入全国医保结算系统。交付一个以题目给出的示例城市 A 和 B 为政策数据的住院报销预估产品，展示用户输入、确定性计算、结果解释，以及政策数据从离线处理到在线服务的完整边界。

交付包含两种可运行形态：

- 离线演示版：不启动服务，直接打开静态 H5 即可演示输入、计算与结果解释。
- 启动服务版：使用 Next.js 和 TypeScript 提供前端页面与 HTTP API；浏览器通过 API 请求服务端的政策查询、缓存和确定性计算能力。

两种形态共用同一套领域规则和政策模型。离线版使用只读政策快照；服务版的政策数据、缓存、计算轨迹和审计都只存在于服务端边界。

本 MVP 明确标注为示例政策和报销预估，不接入真实个人参保信息、真实全国政策或真实医保结算。

## 用户与成功标准

评审者可以选择城市 A 或 B，填写或使用预置样例填充住院费用条件，获得预计自费、基本医保报销、大病保险报销和逐项计算依据。评审者还可以在同一页面查看架构说明，或通过脚本观察模拟的政策采集、AI 提取建议、人工审核、发布与缓存失效流程。

成功标准：

- 离线版和服务版针对相同输入给出相同金额和政策版本。
- 前端不会持有完整政策规则，也不会自行产生服务版计算结果。
- 报销引擎、缓存、政策发布和 API 均有自动化测试。
- 每次服务版计算可返回地区、政策版本、缓存状态和可读的计算轨迹。
- AI 的输出只能成为待审核草稿，不能直接进入已发布政策。

## 输入和计算口径

MVP 覆盖住院场景。用户输入或选择：城市、医院等级、总医疗费用、目录外自费费用、乙类药品或项目总费用、年度已报销累计、是否异地备案；城市 A 还选择在职或退休。

城市 A 为职工医保示例：社区、二级、三级医院起付线分别为 200、400、800；在职报销比例为 90%、85%、80%；退休在对应比例基础上加 5 个百分点；乙类先行自付为 10%；年度封顶线为 400000；异地未备案降低 20 个百分点；封顶线以上部分按 0 至 50000 元 60%、50000 至 100000 元 65%、100000 元以上 70% 的阶梯报销。

城市 B 为居民医保示例：社区、二级、三级医院起付线分别为 100、300、600；报销比例为 85%、75%、65%；乙类先行自付为 15%；年度封顶线为 200000；异地未备案降低 15 个百分点。题目未给出城市 B 的大病保险阶梯，MVP 将其作为未配置能力显示为 0，而非编造规则。

计算引擎使用下列明确口径：

1. `乙类先行自付 = 乙类费用 × 乙类先行自付比例`。
2. `可报销基数 = max(0, 总费用 - 目录外费用 - 乙类先行自付 - 起付线)`。
3. `实际报销比例 = max(0, 基础报销比例 + 退休加点 - 未备案降点)`。
4. `理论基本医保报销 = 可报销基数 × 实际报销比例`。
5. `剩余封顶额度 = max(0, 年度封顶线 - 年度已报销累计)`。
6. `基本医保报销 = min(理论基本医保报销, 剩余封顶额度)`。
7. `封顶线以上待计算金额 = max(0, 理论基本医保报销 - 剩余封顶额度)`；仅在已配置大病保险阶梯时，按累进区间计算大病保险报销。
8. `预计自费 = max(0, 总费用 - 基本医保报销 - 大病保险报销)`。

所有金额以分作为领域层计算单位，界面仅在展示时转换为人民币两位小数。每步都写入计算轨迹。

## 架构与运行数据流

### 离线演示版

离线 H5 打包一份只读的城市 A/B 已发布政策快照和可在浏览器运行的纯规则引擎。它不调用网络，不模拟 Redis，也不声称具备实时更新能力。样例按钮只写入表单条件，仍调用同一个领域引擎得到结果。

### 启动服务版

服务版的浏览器页面只负责采集输入、调用 API、渲染服务器结果和展示架构说明。它不读取政策文件，不执行报销规则。

`POST /api/v1/reimbursement-calculations` 接收计算请求。HTTP 层完成参数校验后调用应用层用例；用例经服务端 TTL 缓存读取已发布政策，缓存未命中时从政策仓库回源；领域引擎计算金额和轨迹；API 返回金额、轨迹、政策版本、缓存命中状态与追踪标识。

服务端政策缓存以 `region:benefitPlan:effectiveDate:version` 为键。MVP 采用内存 TTL 实现，并通过接口保留 Redis 适配点。发布新政策时主动失效关联键。政策仓库在 MVP 读取本地已发布 JSON，生产替换点为关系数据库或配置服务。

### 离线政策处理

Worker 不在用户计算请求中运行。它依次执行：读取原始政策材料、产出结构化提取建议、运行模式和金额校验、等待人工审核、发布政策版本、使旧缓存失效。MVP 的原始材料为本地 JSON 或文本夹具，提取建议为可替换的 AI 适配器模拟结果。只有人工审核服务调用发布用例，AI 适配器没有发布权限。

## 模块布局

```text
apps/
  offline-demo/              静态 H5 与只读快照适配器
  service-web/               Next.js 页面、API 路由和服务组合根
packages/
  domain/                    政策模型、金额对象、规则匹配、报销引擎、轨迹
  application/               计算、审核、发布和政策同步用例
  contracts/                 请求响应 DTO、枚举和运行时校验模式
  infrastructure/            文件政策仓库、TTL 缓存、审计日志、AI 和来源适配器
worker/                       离线处理 CLI 入口
data/
  raw-policy-sources/        示例原始政策材料
  policy-drafts/             待审核提取建议
  published-policies/        审核完成的城市 A/B 政策版本
tests/                        单元、集成和 API 合约测试
docs/                         架构图、演示剧本和运行说明
```

`domain` 不引用 Next.js、文件系统、缓存或 AI。`application` 只依赖端口接口。`infrastructure` 实现这些接口。Next API 路由只做输入输出适配和依赖注入，不含报销公式。

## 页面与交互

页面提供“报销测算”和“方案设计”两个视图。

报销测算视图包含城市切换、城市 A 的在职或退休选择、医院等级、费用输入、异地备案开关、年度累计输入和两个样例填充按钮。计算前对负数、目录外费用大于总费用、乙类费用大于总费用等条件给出就近中文错误。计算后显示总费用、预计自费、基本医保报销和大病保险报销；展开的计算清单逐项解释每个中间值。服务版额外展示政策版本、来源状态、请求追踪标识和缓存命中状态。

方案设计视图展示两条数据流：离线的政策处理流和在线的用户请求流。它还用清晰表格划分 AI 可做的文档抽取和差异发现，与 AI 禁止做的报销金额决定、无审核发布和政策编造；并说明缓存横向扩展与金标回放验证。

页面使用简体中文、响应式单列优先布局、原生语义表单控件、键盘可访问状态和可读错误提示。

## API 契约

计算请求字段为 `region`、`hospitalLevel`、`employmentStatus`、`totalAmountFen`、`outOfCatalogAmountFen`、`classBAmountFen`、`annualReimbursedAmountFen` 与 `outOfAreaFiled`。城市 B 不接受退休状态。

成功响应包含 `calculationId`、`policyVersion`、`cacheStatus`、`result` 和 `trace`。`result` 包含预计自费、基本医保报销、大病保险报销和可报销基数，金额均为分。`trace` 是稳定排序的规则步骤，包含标签、输入值、输出值和所用规则。没有已发布政策或输入无效时，API 返回可恢复的中文错误码和消息，不返回猜测金额。

## 验证策略

- 领域层金标用例覆盖两座城市、三个医院等级、退休加点、未备案降点、乙类先行自付、封顶线和城市 A 大病保险全部区间。
- 属性测试验证金额不为负、报销不超过总费用、已报销累计上升不会提高基本医保报销。
- 缓存测试验证第一次请求未命中、同版本第二次命中、发布新版本后失效。
- 发布测试验证未审核草稿无法进入已发布仓库，发布版本必须附有效期和来源标识。
- API 测试验证浏览器无法传入或覆盖政策比例，且结果带有版本和轨迹。
- 对相同输入运行离线与服务版，断言金额和轨迹一致。

## 非目标与生产替换点

本 MVP 不实现真实政府站点接入、真实 OCR/LLM、真实身份认证、真实支付结算、真实 Redis/数据库或全量统筹区覆盖。代码通过端口接口和文档说明这些替换点：官方来源连接器、AI 提取器、人工审核工作台、关系型政策仓库、Redis 缓存、消息队列和可观测性平台。

## 演示顺序

1. 打开离线版，点击城市 A 样例，展示分项结果和计算轨迹。
2. 修改医院等级、退休状态或异地备案，展示政策条件如何改变结果。
3. 启动服务版，使用相同输入，展示 API 返回的相同结果、版本和缓存状态。
4. 再次发起相同请求，展示缓存命中。
5. 运行 Worker，展示原始材料如何形成待审核草稿；审核并发布后展示缓存失效和新版本生效。
6. 打开方案设计视图，说明 AI 边界、规模方案和正确性验证。
