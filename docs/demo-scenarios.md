# 七分钟评测演示剧本

## 0:00–1:00：先说明边界

打开离线 `dist/index.html`，指出“示例政策，仅供演示”。说明此项目交付的是 24 小时内可评估的 MVP：两座示例城市、住院场景、明确的生产替换入口，而非真实医保结算。

## 1:00–2:30：离线交互和解释性

点击“填入城市 A 样例”，再点击“开始测算”。展示预计自费、基本医保与大病保险金额；展开“计算明细”，说明乙类先行自付、起付线、基数、比例、封顶线和最终自费都可追溯。切换退休状态或取消异地备案，观察条件变化。

## 2:30–3:30：离线模式的诚实边界

打开浏览器网络面板或说明自动化测试，确认离线 H5 不调用 `/api`。它使用只读快照，因此适合演示与离线体验，不宣称实时政策。

## 3:30–5:00：服务端计算边界

运行 `pnpm run dev:service`，访问 `http://localhost:3000`。点击城市 B 样例并测算：结果区展示 `B-2026.01`、请求标识和缓存状态。再次提交相同输入，缓存状态应变为“命中”。强调浏览器不能提交政策比例，也不会在 API 失败时自行计算。

## 5:00–6:00：政策治理与 AI 边界

运行 `pnpm run worker:demo`。依次解释本地材料、`pending_review` 的 AI 提案、审核人、发布版本和缓存失效。AI 的权限止于草稿，发布由 `PolicyPublisher` 控制。

## 6:00–7:00：生产演进与正确性

打开两版的方案说明，或参照 [architecture.md](architecture.md)。指出替换顺序：先稳定规则和契约，再接入真实来源/审核，随后替换数据库/Redis，最后完成服务化、安全和可观测性。最后运行 `pnpm run verify` 展示自动化验证。

## 建议回答

- **为什么不是纯前端？** 服务版将政策匹配、缓存、审计和确定性计算集中在后端；离线版只是受控演示形态。
- **AI 怎么保证安全？** AI 只可生成带来源标识的待审核草稿，不能发布、不能决定金额，发布后还会触发版本缓存失效。
- **如何扩展到生产？** 不替换领域公式或 API DTO，只把基础设施端口的本地实现替换为真实来源、数据库、Redis、队列与观测系统。
