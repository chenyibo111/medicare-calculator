    仓库真实进度

    PostgreSQL 政策持久化、Redis 缓存与 Outbox 已实现

    这不是页面上的概念图：服务版 Compose 已连接真实 PostgreSQL、Redis，并可用一条命令复跑“迁移 → 种子 → 两次测算 → Redis 命中 → PostgreSQL 审计”的证据链。

    已实现 · 在线消费

    已发布政策与计算证据

    1. 版本化持久化已发布政策、审核记录、计算审计均写入 PostgreSQL；计算响应携带政策版本和缓存状态。
    2. Redis 精准失效缓存键关联政策版本；发布 Outbox 被消费后，旧版本键失效、新版本键预热。

    01 · 生产运行链路

    生产系统的离线与在线数据流

    离线链路负责生产可信政策，在线链路只消费已发布政策并返回测算结果。

    后台批处理 · 非用户请求路径

    政策生产链路（离线）

    1. 定时获取与原文留档采集官方公告 / 附件，保存来源、文件哈希与原始证据
    2. 结构化与人工审核OCR / AI 生成带证据定位的草稿，双人审核规则字段与样例
    3. 版本发布与缓存预热审批后的政策版本写入仓库，发布事件使在线缓存精准失效并预热

    低频、可重试、可回放；失败进入队列或人工工作台，不阻塞任何用户测算。

    高频同步链路 · 面向用户请求

    用户测算链路（在线）

    1. 客户端 / 网关接收测算条件，在边界完成鉴权、限流、幂等与参数校验
    2. 政策缓存 / 计算用例按地区与版本读取已发布政策，调用确定性规则引擎
    3. 结果与异步审计同步返回金额、版本、轨迹和请求 ID；日志指标异步进入队列

    在线请求不调用模型、不解析原文、不等待写库；浏览器不保存政策比例或结算公式。

    02 · 人机边界

    AI 的能力边界

    AI 的价值在于降低政策录入与变更识别成本；金额结果必须来自可复现的规则代码和已审批版本。

    允许辅助

    AI 可以辅助的环节

    • OCR 识别政策附件并定位原文证据
    • 提取起付线、比例、封顶线等候选字段
    • 标出新旧政策版本的条款差异
    • 生成待审核草稿与测试建议

    绝对禁止

    AI 不得参与的环节

    • 根据语义直接计算或修改报销金额
    • 自动发布、回滚或覆盖已生效政策
    • 在规则冲突时自行裁决适用口径
    • 把真实个人医疗数据作为提示词内容

    原因：模型输出具有概率性；医保结算需要确定性、可追溯、可审核，并符合最小数据暴露原则。

    03 · 政策治理

    政策数据如何获取、结构化、更新与发布

    政策本身是受治理的版本化资产，而不是由页面或模型临时“猜出”的参数。

    1. 官方来源接入官网公告、公开附件或人工受控录入；记录来源 URL、抓取时间与文件哈希。
    2. 原文留档对象存储保存原始文件，保留可追溯证据，不直接覆盖历史版本。
    3. 结构化候选OCR / AI 提取规则字段，同时保存页码、段落等证据定位。
    4. 双人审核业务审核与技术审核核对来源、字段、边界样例和生效日期。
    5. 版本化发布审批 ID、版本号、生效窗口和回滚版本一并写入；只有审批通过的草稿可发布。
    6. 事件驱动生效发布事件使缓存失效并预热新版本；异常可切回上一已批准版本。

    04 · 容量设计

    千万日活：性能与成本

    评测容量假设：1,000 万 DAU × 人均 2 次测算/日，若 10% 集中到峰值小时并预留 3 倍余量，按约 1,700 RPS 设计；上线后再用真实曲线校准。

    无状态计算服务API 可按 CPU / RPS 横向扩缩；计算只读已发布政策。
    缓存优先读取Redis 按地区与政策版本缓存，发布事件精准失效并热点预热。
    异步写入审计请求日志、指标与政策处理走队列，避免写库阻塞测算主链路。
    LLM 不在请求路径AI 只在低频政策处理使用，令高频测算成本可预测、可压缩。

    05 · 正确性

    如何证明算得对

    不是仅看一笔结果“看起来合理”，而是让每个政策版本、每条规则与每次计算都能被复算和追责。

    固定样例回归每个已发布版本有经人工复核的黄金结算单；版本变更必须全量比对。
    边界与性质测试覆盖 0 元、起付线、封顶线、异地未备案等边界；校验“报销 + 自费 = 总费用”。
    双轨灰度核对新规则先镜像计算，与现网批准版本和人工复算结果比较，异常不放量。
    可追溯与回滚结果携带政策版本、计算轨迹和请求 ID；异常分布触发告警，可回滚政策版本。
    当前替换进度：Compose 服务版已使用 PostgreSQL、Redis 与发布 Outbox；离线 H5 仍只读打包快照。下一阶段只替换真实来源接入、附件留档和受控 AI 草稿，应用用例、API 契约和确定性规则引擎保持不变。
